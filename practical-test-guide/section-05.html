Practical Testing: 실용적인 테스트 가이드

5. Presentation Layer 테스트

Presentation Layer

  • 외부 세계의 요청을 가장 먼저 받는 계층이다.
  • 파라미터에 대한 최소한의 검증을 수행한다.

비즈니스 로직을 전개시키기 전에 값들이 유효한가에 대한 검증을 하는 게 최우선이므로, 그런 부분을 중점으로 테스트를 작성하면 좋다. Persistence Layer와 Business Layer는 스프링을 통으로 띄워서 통합 테스트를 진행했지만, Presentation Layer를 테스트할 때는 하위의 두 레이어를 Mocking 처리해서 정상 동작한다고 가정하고, 테스트하고자 하는 레이어에만 집중해서 테스트한다.

MockMvc

Mock(가짜) 객체를 사용해 스프링 MVC 동작을 재현할 수 있는 테스트 프레임워크. 어떤 객체나 레이어를 테스트할 때 의존관계를 갖고 있는 것들을 준비해야 할 게 너무 많을 때, 가짜로 잘 동작하는 걸 가정하고 처리하고 싶을 때 사용한다.

요구사항

  • 관리자 페이지에서 신규 상품을 등록할 수 있다.
  • 상품명, 상품 타입, 판매 상태, 가격 등을 입력받는다.

Presentation Layer: Controller Test 작성하기

@WebMvcTest

  • 전체 Bean Context를 올려서 사용하는 @SpringBootTest 대신, 컨트롤러만 떼서 관련 빈들만 올려서 테스트할 수 있는 가벼운 어노테이션이다. 
@WebMvcTest(controllers = ProductController.class)
class ProductControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean
    private ProductService productService;
}

테스트하고자 하는 컨트롤러를 명시하면 된다.

@MockBean, @Mock

  • spring-boot-starter-test를 쓰면 자동으로 mockito(모킹 프레임워크)가 포함되어 있다.
  • @MockBean은 목 객체를 만들어 대신 빈으로 넣어주는 역할을 한다. 예를 들어 ProductController 빈을 생성하면 ProductService가 없다고 나올 것이므로 @MockBean 처리를 해야 예외가 터지지 않는다.

mockMvc.perform()

  • API를 날리는 동작을 수행한다.
  • 괄호 내부에 수행에 필요한 정보들을 넣을 수 있다.
mockMvc.perform(
    post("/api/v1/products/new")
        .content(objectMapper.writeValueAsString(request))
        .contentType(MediaType.APPLICATION_JSON)
)

post 같은 경우는 http body의 값을 넣다 보니 직렬화/역직렬화 과정을 거치게 된다. 만든 object를 JSON 형태로 직렬화해서 byte 배열이나 string 형태로 content에 넣어주면 되는데, 이 직렬화를 위해 ObjectMapper를 @Autowired로 테스트에 포함시킨다. ObjectMapper는 JSON과 Object 간의 직렬화·역직렬화를 도와주고, contentType은 JSON 타입을 헤더에 명시해준다.

  • 검증은 .andExpect(MockMvcResultMatchers.status().isOk());처럼 체이닝식으로 걸어서 확인한다.
  • .andDo(MockMvcResultHandlers.print())를 쓰면 자세한 로그를 찍어볼 수 있다.

트러블슈팅 참고

  • 오류 1: Error creating bean with name 'jpaMappingContext': JPA metamodel must not be empty — @SpringBootApplication 위에 달아놓은 @EnableJpaAuditing 관련 문제. config로 따로 관리해주면 해결된다.
  • 오류 2: MockHttpServletResponse: Status = 400 Error message = Invalid request content. — 컨트롤러에 @RequestBody를 달았는지 확인한다.
  • 오류 3: java.lang.IllegalStateException: Cannot resolve parameter names for constructor — 스프링 버전이 올라가면서 체크해야 할 문제. build.gradle에 정리해둔다.
  • 오류 4: H2 Console Sorry, remote connections ('webAllowOthers') are disabled on this server. — 아래처럼 yml 설정을 추가한다. 
h2:
  console:
    enabled: true
  settings:
    web-allow-others: true
