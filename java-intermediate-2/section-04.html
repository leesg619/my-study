김영한의 실전 자바 - 중급 2편

4. 컬렉션 프레임워크 - LinkedList

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 2편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

왜 노드와 연결인가

  • 배열 리스트의 약점 두 가지: 미리 잡아 둔 뒤쪽 공간의 메모리 낭비, 앞·중간 추가·삭제 시 데이터를 옮기는 쉬프트 비용.
  • 해결 아이디어: 칸을 미리 잡지 않고, 데이터가 생길 때마다 작은 객체를 만들어 구슬 꿰듯 참조로 연결한다.
public class Node {
    Object item;
    Node next;

    public Node(Object item) { this.item = item; }
}

Node first = new Node("A");
first.next = new Node("B");
first.next.next = new Node("C");

Node x = first;
while (x != null) {       // 모든 노드 탐색
    System.out.println(x.item);
    x = x.next;           // 다음 노드로 이동
}
  • 노드 = 내 데이터(item) + 다음 노드의 참조(next). 마지막 노드의 next는 null이다.
  • 핵심은 x = x.next. 참조를 따라 한 칸씩 옮겨 가다 null을 만나면 끝난다.
  • 처음엔 머릿속으로만 따라가기 어렵다 → 종이에 그림을 그려 보면 이해가 쉽다. 이 구조를 넘어야 트리, 그래프 같은 다음 자료 구조로 나아갈 수 있다.

기본 연산 만들어 보기

private static Node getLastNode(Node node) {
    Node x = node;
    while (x.next != null) { // next가 null이면 마지막 노드
        x = x.next;
    }
    return x;
}

private static Node getNode(Node node, int index) {
    Node x = node;
    for (int i = 0; i < index; i++) { // 인덱스 횟수만큼 따라간다
        x = x.next;
    }
    return x;
}

private static void add(Node node, Object param) {
    getLastNode(node).next = new Node(param);
}
  • 디버깅을 위해 toString()을 직접 구현한다. IDE가 만든 코드는 next의 toString()을 재귀로 불러 Node{item=A, next=Node{item=B, ...}}처럼 읽기 힘들다 → StringBuilder와 반복문으로 [A->B->C] 모양을 만든다. 반복문 안에서 문자열을 더하므로 StringBuilder가 적합하다.
  • 필요한 만큼만 노드를 만들어 공간 낭비가 없다. 다만 next 참조를 보관하는 비용은 노드마다 추가로 든다.

직접 만드는 연결 리스트

  • 겉으로 보이는 기능은 배열 리스트와 같다 — 순서 있고, 중복 허용하는 리스트. 구현이 다르므로 성능 특성이 다르다. 그래서 연결 리스트에는 초기 크기를 정하거나 공간을 늘리는 코드(grow())가 필요 없다.
  • 필드는 첫 노드의 참조 first와 개수 size뿐이다.
public class MyLinkedListV1 {
    private Node first;
    private int size = 0;

    public void add(Object e) {
        Node newNode = new Node(e);
        if (first == null) {
            first = newNode;
        } else {
            getLastNode().next = newNode;
        }
        size++;
    }

    public Object get(int index) { return getNode(index).item; }

    public Object set(int index, Object element) {
        Node x = getNode(index);
        Object oldValue = x.item;
        x.item = element;
        return oldValue;
    }
}
  • get/set은 getNode(index)로 위치를 찾아야 하므로 O(n). 연결 리스트의 인덱스는 실제로 있는 게 아니라 "맨 앞에서 몇 번째"라는 가정일 뿐이다 → 배열처럼 주소를 계산할 수 없다.
  • indexOf()는 노드를 돌며 equals()로 비교한다 → O(n). 배열 리스트의 테스트 코드를 그대로 가져와도 똑같이 동작한다.

추가·삭제 — 참조만 바꾸면 된다

작업방법빅오
맨 앞 추가새 노드의 next → 기존 first, first → 새 노드O(1)
맨 앞 삭제first → 다음 노드, 지운 노드의 필드는 nullO(1)
중간 추가직전 노드를 찾은 뒤, 새 노드의 next → 직전의 next, 직전의 next → 새 노드찾기 O(n) + 연결 O(1)
중간 삭제직전 노드의 next → 지울 노드의 next찾기 O(n) + 연결 O(1)
 
public void add(int index, Object e) {
    Node newNode = new Node(e);
    if (index == 0) {
        newNode.next = first;
        first = newNode;
    } else {
        Node prev = getNode(index - 1);
        newNode.next = prev.next;
        prev.next = newNode;
    }
    size++;
}

public Object remove(int index) {
    Node removeNode = getNode(index);
    Object removedItem = removeNode.item;
    if (index == 0) {
        first = removeNode.next;
    } else {
        Node prev = getNode(index - 1);
        prev.next = removeNode.next;
    }
    removeNode.item = null;
    removeNode.next = null;
    size--;
    return removedItem;
}
  • 참조를 바꾸는 순서가 중요하다. prev.next를 먼저 덮어쓰면 뒤쪽 노드로 가는 길을 잃는다.
  • 인덱스 0일 때는 first를 바꿔야 하므로 로직이 갈린다. 코드만 봐서는 헷갈리니 그림을 먼저 그리고 코딩하는 게 낫다.
  • 배열은 쉬프트 때문에 전체 데이터가 움직이지만, 연결 리스트는 관련된 참조만 살짝 바꾼다. 나머지 노드는 무슨 일이 있었는지 모른다.

배열 리스트 vs 연결 리스트

연산배열 리스트연결 리스트
인덱스 조회O(1)O(n)
검색O(n)O(n)
앞에 추가·삭제O(n) (쉬프트)O(1)
뒤에 추가·삭제O(1)O(n) (마지막 노드까지 탐색)
중간에 추가·삭제O(n) (쉬프트)O(n) (탐색)
  • 성질이 정반대다. 조회가 많거나 뒤에서 넣고 빼는 작업이 많으면 배열 리스트, 앞에서 넣고 빼는 작업이 많으면 연결 리스트.
  • 중간 작업은 둘 다 O(n)이지만 앞쪽에 가까울수록 연결 리스트가 유리하다.
  • 지금 만든 건 한 방향으로만 가는 단일 연결 리스트다. 자바의 LinkedList는 앞뒤로 모두 가는 이중 연결 리스트이고 마지막 노드 참조(last)도 있어서, 뒤쪽 추가·삭제도 O(1)이다.

제네릭 도입과 중첩 클래스

public class MyLinkedListV3<E> {
    private Node<E> first;
    private int size = 0;

    public void add(E e) { ... }
    public E get(int index) { return getNode(index).item; }

    private static class Node<E> {
        E item;
        Node<E> next;

        public Node(E item) { this.item = item; }
    }
}
  • Object로 되어 있던 곳을 모두 E로 바꾼다.
  • Node는 리스트 내부에서만 쓰이므로 정적 중첩 클래스로 넣어 감춘다 → 응집도가 높아지고, 바깥 Node보다 안쪽 선언이 우선된다.
  • 배열과 달리 new Node<>(e)는 문제없이 생성되므로 Object[] 같은 우회가 필요 없다.

정리

  • 연결 리스트 = 노드 + 참조. 공간 낭비가 적지만 인덱스로 찾아가는 데 O(n)이 걸리는 게 치명적인 약점이다.
  • 앞쪽 작업은 O(1)로 배열 리스트와 정반대의 강점을 가진다.
  • 배열 리스트와 연결 리스트는 기능이 같고 구현만 다르다. 비슷하면 할 수 있는 게 있다 → 다음 챕터의 추상화.
