김영한의 실전 자바 - 중급 1편

4. 래퍼, Class 클래스

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 1편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

기본형의 한계

  • 자바는 객체지향 언어인데, int·double 같은 기본형은 객체가 아니다. 그래서 두 가지 한계가 생긴다.
  • 한계 1 — 기능을 못 가진다: 기본형은 메서드를 가질 수 없어서, 두 값을 비교하려면 compareTo(a, b)처럼 외부 메서드에 의존해야 한다. 객체라면 a.compareTo(b)처럼 스스로 기능을 캡슐화할 수 있다.
  • 한계 2 — "값 없음"을 표현 못 한다: 기본형은 항상 값을 가져야 해서, 배열에서 값을 못 찾았을 때 -1이나 0 같은 특정 값으로 "없음"을 표시해야 한다. 그런데 그 특정 값이 실제 데이터로 존재할 수도 있어서 모호함이 생긴다 (-1을 못 찾음 표시로 썼는데 배열에 진짜 -1이 있다면?).
  • → 참조형(객체)은 null이라는 명확한 "없음" 값을 쓸 수 있다는 점에서 이 한계를 해결할 실마리가 된다. (다만 NullPointerException 위험은 감수해야 함.)
  • 기본형이 항상 값을 가져야 한다는 제약 자체는 나쁜 게 아니다 — 오히려 값 누락 실수를 막아주는 장치이기도 하다. 다만 "값 없음"을 표현해야 하는 상황에서는 한계가 된다.

래퍼 클래스

  • 래퍼 클래스(Wrapper Class): 기본형을 객체로 감싼 것. int→Integer, long→Long처럼 대부분 기본형 이름 앞글자를 대문자로 바꾼 이름.
  • 모두 final로 선언된 불변 객체다. 객체이므로 비교할 때는 ==이 아니라 equals()를 써야 한다.
  • 생성 방법: new Integer(10)은 Deprecated(사용 지양) — 대신 Integer.valueOf(10)을 쓴다. valueOf()는 -128~127 범위의 자주 쓰는 값을 미리 캐싱해뒀다가 재사용해서 new보다 효율적이다 (문자열 풀과 비슷한 원리).
  • 내부 기본값 꺼내기: intValue(), longValue() 등.
  • 박싱(Boxing): 기본형 → 래퍼 객체 (물건을 상자에 넣는 것). 언박싱(Unboxing): 래퍼 객체 → 기본형 (상자에서 꺼내는 것).
  • 오토 박싱/언박싱(Java 5+): Integer i = 7;, int n = i;처럼 직접 valueOf()/intValue()를 안 적어도 컴파일러가 자동으로 넣어준다.

래퍼 클래스와 성능

  • valueOf()는 래퍼 타입을 반환하고, parseInt()는 기본형을 반환한다 — 필요한 반환 타입에 맞춰 선택.
  • 래퍼 클래스는 객체라서 메타데이터·객체 관리 오버헤드가 붙는 만큼 기본형보다 느리다 — 10억 번 덧셈 테스트에서 기본형 long은 0.3초, Long은 1.5초로 약 5배 차이.
  • 하지만 일반적인 애플리케이션에서 이 정도 차이는 체감하기 어렵다. 특히 웹 애플리케이션에서는 메모리 연산보다 네트워크 호출(DB, 외부 API)이 훨씬 큰 병목이라, 이런 미시적 성능 차이에 집착하는 건 대개 낭비다.
  • 실무 원칙: 우선 유지보수하기 좋은 코드로 개발하고, 실제 성능 테스트로 병목 지점을 찾은 뒤 그 지점만 최적화한다.

Class 클래스

  • Class는 클래스 자체의 메타 정보(이름, 상위 클래스, 인터페이스, 필드, 메서드 등)를 다루는 클래스다.
  • Class 객체를 얻는 3가지 방법: String.class(타입으로 직접), instance.getClass()(인스턴스로부터), Class.forName("패키지.클래스명")(문자열로 — ClassNotFoundException 체크 예외가 있어서 throws 처리 필요).
  • 주요 기능: getDeclaredFields()(필드 조회), getDeclaredMethods()(메서드 조회), getSuperclass()(상위 클래스), getInterfaces()(구현 인터페이스).
  • getDeclaredConstructor().newInstance()로 Class 메타 정보만 가지고 동적으로 인스턴스를 생성할 수도 있다 — 이런 식으로 메타 정보를 활용해 메서드 호출·인스턴스 생성까지 하는 기술을 Reflection이라 부른다.
  • 참고로 Class는 자바 예약어라 변수명으로 못 쓴다 — 관례상 clazz라고 쓴다.
  • Reflection은 최신 프레임워크 내부에서 많이 쓰이지만, 지금 단계에서는 "Class라는 게 있고 메타 정보를 다룬다" 정도만 알아둬도 충분하다.

System, Math, Random 클래스

  • System: currentTimeMillis()/nanoTime()(시간 측정), getenv()(OS 환경 변수), getProperty("java.version")(자바 시스템 속성), arraycopy()(시스템 레벨 최적화로 일반 반복문 복사보다 빠른 배열 복사), exit()(즉시 종료 — 뒷정리 로직이 안 돌 수 있어 웹 애플리케이션 등에서는 권장하지 않음).
  • Math: max()/min()/abs(), ceil()(올림)/floor()(내림)/round()(반올림), sqrt(), random()(0.0~1.0 미만 double). 아주 정밀한 소수 계산이 필요하면 BigDecimal을 쓴다.
  • Random: Math.random()보다 다양한 난수를 제공한다(내부적으로 Math.random()도 Random을 사용). nextInt(bound)는 0 이상 bound 미만의 정수를 반환 — 범위를 옮기려면 nextInt(10) + 1처럼 오프셋을 더한다.
  • seed: 같은 seed를 주면 항상 같은 순서로 난수가 나온다. seed를 안 주면 나노초 등으로 매번 다르게 결정된다. 테스트 코드에서 결과를 고정해서 검증하거나, 게임에서 같은 지형을 재현할 때 유용하다.

정리

  • 기본형은 객체가 아니라서 메서드를 가질 수 없고 null로 "값 없음"을 표현할 수도 없다 — 래퍼 클래스가 이 한계를 보완한다.
  • 래퍼 클래스는 모두 불변 객체이며, 비교는 반드시 equals(). 생성은 new보다 캐싱을 활용하는 valueOf()가 낫다.
  • 박싱/언박싱은 자바 5부터 오토 박싱/언박싱으로 자동화되어 변환 코드를 직접 쓸 필요가 없다.
  • 래퍼 클래스가 기본형보다 느리지만, 실무에서는 그 차이보다 유지보수성과 실제 병목(특히 네트워크 호출) 개선이 우선이다.
  • Class는 클래스의 메타 정보를 다루며, 세 가지 방법(.class, getClass(), forName())으로 얻을 수 있고 Reflection의 기반이 된다.
  • System·Math·Random은 시간·시스템 정보·수학 연산·난수 생성을 제공하는 자바 표준 유틸리티 클래스다.
