김영한의 실전 자바 - 기본편

1. 클래스와 데이터

인프런 김영한 강사님의 "김영한의 실전 자바 - 기본편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

클래스가 왜 필요한가

  • 학생 여러 명의 이름·나이·성적을 각각 변수로 선언하면, 학생이 늘어날 때마다 변수 선언과 출력 코드를 계속 추가해야 한다 — 코드 변경이 끝없이 늘어난다.
  • 배열로 바꾸면(names[], ages[], grades[]) 학생 수가 늘어도 배열에 값만 채우면 되니 코드 변경은 줄어든다. 하지만 한 학생의 데이터가 세 개의 배열에 흩어져 있어서, 학생 하나를 지우거나 수정하려면 세 배열의 같은 인덱스를 일일이 찾아 맞춰야 한다 — 사람이 관리하기엔 실수하기 쉬운 구조.
  • 사람은 "학생"이라는 개념을 이름·나이·성적을 한데 묶은 하나의 단위로 다루고 싶어 한다. 이렇게 관련 데이터를 하나의 묶음으로 관리하게 해주는 것이 클래스다.

클래스 도입

  • 클래스는 어떤 개념(학생)을 표현하는 틀이며, 그 안에 선언한 변수를 멤버 변수(필드)라고 부른다. 클래스 이름은 관례상 대문자로 시작하는 낙타 표기법을 쓴다.
  • int, String처럼 자바가 기본 제공하는 타입이 있듯, 클래스를 정의하면 Student처럼 내가 원하는 사용자 정의 타입을 직접 만들 수 있다 — 클래스는 이 사용자 정의 타입의 설계도 역할을 한다.
  • new Student()로 실제 메모리에 만들어낸 실체를 객체(인스턴스)라고 한다. new는 "메모리에 새로 만들어라"는 뜻이고, 생성이 끝나면 그 객체에 접근할 수 있는 참조값(주소)을 돌려준다 — 이 참조값을 변수에 담아둬야 나중에 객체를 다시 찾아갈 수 있다.
  • new를 호출할 때마다 메모리에 별도의 객체가 새로 생긴다. student1과 student2는 같은 Student 타입이라도 서로 다른 참조값을 가진 완전히 독립된 객체다.
class Student {
    String name;
    int age;
    int grade;
}

Student student1 = new Student(); // 참조값이 student1에 저장됨
student1.name = "김영한";
student1.age = 20;

객체 사용 — 점(.) 연산자

  • 객체의 멤버 변수에 접근할 때는 student1.name처럼 점(.)을 사용한다. 점 연산자는 student1 변수에 저장된 참조값을 읽어서, 실제 메모리에 있는 객체로 찾아가는 역할을 한다.
  • 값을 대입할 때(student1.name = "값")와 값을 읽을 때(System.out.println(student1.name)) 모두 동일하게 참조값을 통해 객체에 접근한 뒤 멤버 변수를 다룬다 — 접근 방식 자체는 같고 대입이냐 읽기냐만 다르다.

클래스, 객체, 인스턴스 정리

  • 클래스 = 붕어빵 틀, 자동차 설계도처럼 속성과 기능을 정의하는 틀. 틀 자체는 먹거나 탈 수 없는 개념적인 존재다.
  • 객체/인스턴스 = 그 틀로 실제로 찍어낸 팥 붕어빵, 실제로 생산된 자동차. new로 만들어지며 각자 독립된 상태(멤버 변수 값)를 가진다.
  • 객체와 인스턴스는 사실상 같은 말이다. 다만 "student1은 Student 클래스의 인스턴스다"처럼 어떤 클래스로부터 만들어졌는지를 강조하고 싶을 때 인스턴스라는 표현을 쓰는 경우가 많다 — 실무에서는 대부분 구분 없이 섞어 쓴다.

배열 도입으로 리팩토링

  • 학생이 늘어날 때마다 Student student3, student4 ...를 계속 선언하는 대신, Student[] 배열 하나로 여러 학생 객체를 묶어 관리할 수 있다 — 배열도 new로 만들어지고, 만들어지면 참조값을 돌려받는다는 점은 객체와 동일하다.
  • 배열을 갓 생성하면 아직 아무 객체도 담기지 않아 각 칸이 null이다. students[0] = student1;처럼 대입하면, 이는 student1에 들어있는 참조값을 복사해서 배열 칸에 넣는 것 — 학생 객체 자체가 복제되는 게 아니다.
  • 배열 안의 객체 멤버에 접근할 때는 students[0].name처럼 먼저 배열에 접근([])한 다음 객체에 접근(.)하는 순서로 이어진다.
  • 자바의 대입은 항상 "변수에 들어있는 값의 복사"다 — 기본형이면 값 자체가, 참조형이면 참조값만 복사된다. 인스턴스 실체가 복사되는 일은 없다는 게 핵심 원칙.
  • 일반 for문으로 배열을 순회하던 코드는 향상된 for문(for (Student s : students))으로 바꾸면 인덱스 관리 없이 더 간결해진다.
Student[] students = new Student[2];
students[0] = student1;
students[1] = student2;

for (Student s : students) {
    System.out.println(s.name + " " + s.age);
}

정리

  • 변수 → 배열 → 클래스 순으로 발전한 이유: 흩어진 데이터를 사람이 이해하기 쉬운 하나의 개념(학생)으로 묶기 위해서다.
  • 클래스는 설계도, 객체/인스턴스는 그 설계도로 new 만든 실체, 참조값은 그 실체를 가리키는 주소다.
  • 배열은 []로, 객체는 .으로 메모리에 접근한다는 차이가 있지만 둘 다 new로 만들고 참조값을 변수에 담아 쓴다는 점은 동일하다.
  • 자바의 대입은 언제나 값(기본형) 또는 참조값(참조형)의 복사이며, 이 원칙이 이후 모든 객체지향 내용의 토대가 된다.
