김영한의 실전 자바 - 중급 2편

1. 제네릭 - Generic 1

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 2편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

출발점 — 타입마다 박스를 만들면 중복이 터진다

  • 값을 넣고 꺼내기만 하는 단순한 박스를 생각해 보자. Integer를 담는 IntegerBox, String을 담는 StringBox는 필드 타입만 다르고 구조는 똑같다.
  • Double, Boolean… 담을 타입이 늘어날 때마다 거의 같은 클래스를 하나씩 더 만들어야 한다 → 코드 중복.
  • 타입이 다른 게 문제라면, 모든 타입의 부모인 Object로 합치면 되지 않을까?

Object로 합쳐보기 — 중복은 줄었지만 안전하지 않다

public class ObjectBox {
    private Object value;

    public void set(Object object) { this.value = object; }
    public Object get() { return value; }
}

ObjectBox integerBox = new ObjectBox();
integerBox.set(10);
Integer integer = (Integer) integerBox.get(); // 꺼낼 때마다 다운캐스팅

integerBox.set("문자100");                    // 컴파일은 통과
Integer result = (Integer) integerBox.get();  // ClassCastException
  • 다형적 참조 덕분에 클래스 하나로 모든 타입을 담을 수 있다 → 중복은 해결.
  • 대신 문제가 두 가지 생긴다.
    • 반환 타입이 항상 Object — 자식 타입 변수에 부모 타입을 바로 담을 수 없으니, 꺼낼 때마다 다운캐스팅해야 한다.
    • 잘못된 타입도 들어간다 — set(Object)는 무엇이든 받으므로, 정수용으로 쓰던 박스에 문자열을 넣어도 컴파일러가 막지 못한다 → 꺼내는 순간 런타임에 ClassCastException.
  • 결국 딜레마에 빠진다.
    • 타입별 클래스: 타입 안전성 ○ / 코드 재사용 ✕
    • ObjectBox: 타입 안전성 ✕ / 코드 재사용 ○

제네릭 적용 — 두 마리 토끼를 잡는다

public class GenericBox<T> {
    private T value;

    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

GenericBox<Integer> integerBox = new GenericBox<Integer>(); // 생성 시점에 T = Integer
integerBox.set(10);
// integerBox.set("문자100");   // 컴파일 오류
Integer integer = integerBox.get(); // 캐스팅 불필요

GenericBox<String> stringBox = new GenericBox<>(); // 타입 추론으로 오른쪽 생략
  • 클래스 이름 옆에 <T>를 붙이면 제네릭 클래스다. <>는 모양을 따서 다이아몬드라고 부른다.
  • 클래스를 만들 때는 타입을 정하지 않고 T로 비워 둔다 → 객체를 생성할 때 원하는 타입을 지정하면 T가 그 타입으로 결정된다.
  • 타입이 안 맞으면 컴파일 오류가 나고, 꺼낼 때 캐스팅도 필요 없다 → 코드 재사용 + 타입 안전성 동시 달성.
  • GenericBox<Integer>라고 해서 Integer용 클래스가 실제로 만들어지는 건 아니다. 코드가 그렇게 바뀐 것처럼 컴파일러가 타입 정보를 가지고 검사해 주는 것이다.
  • 타입 추론: new GenericBox<>()처럼 생성부의 타입을 생략할 수 있다. 변수 선언부를 보고 컴파일러가 알아내기 때문이다. 즉, 컴파일러가 타입을 읽어낼 수 있는 곳에서만 생략 가능하고, 변수 선언부에는 타입 정보가 있어야 한다.

용어 정리 — 메서드의 매개변수와 인자에 대응시키기

  • 제네릭의 핵심: 사용할 타입을 미리 결정하지 않는다. 클래스를 정의하는 시점이 아니라 실제로 사용하는 생성 시점으로 결정을 미룬다.
  • 이건 메서드와 똑같은 발상이다. println("hello")처럼 값을 메서드 안에 박아 두면 재사용이 안 되지만, 매개변수로 받으면 값 결정을 호출 시점으로 미룰 수 있다.
메서드제네릭
미루는 대상사용할 값사용할 타입
정의할 때매개변수 (String param)타입 매개변수 (<T>)
사용할 때인자 ("hello")타입 인자 (<Integer>)
  • 제네릭(Generic) = "일반적인, 범용적인". 특정 타입에 묶이지 않고 두루 쓸 수 있다는 뜻.
  • 제네릭 타입: 타입 매개변수를 사용해 정의한 클래스나 인터페이스. GenericBox<T>처럼.
  • 타입 매개변수: 대체될 자리에 쓰는 변수, T.
  • 타입 인자: 사용할 때 넘기는 실제 타입, Integer·String.

관례와 주의할 점

  • 타입 매개변수 이름은 아무렇게나 지어도 동작하지만, 관례상 용도를 나타내는 대문자 한 글자를 쓴다: E(Element), K(Key), N(Number), T(Type), V(Value), 두 번째·세 번째 타입은 S, U, V.
  • class Data<K, V>처럼 여러 개를 한 번에 선언할 수 있다.
  • 타입 인자로 기본형은 못 쓴다 — GenericBox<int> ✕, 래퍼 클래스 GenericBox<Integer> ○.
  • 로우 타입(raw type): new GenericBox()처럼 <>를 통째로 생략한 형태. 내부 타입이 Object로 동작한다.
    • 제네릭이 없던 옛날 코드와의 하위 호환 때문에 남아 있을 뿐이므로 쓰지 말자.
    • Object를 담고 싶다면 new GenericBox<Object>()로 명시한다.

활용 예제 — 동물 박스

Box<Dog> dogBox = new Box<>();
dogBox.set(new Dog("멍멍이", 100));
// dogBox.set(new Cat("냐옹이", 50)); // 컴파일 오류
Dog dog = dogBox.get();

Box<Animal> animalBox = new Box<>();
animalBox.set(new Animal("동물", 0));
animalBox.set(new Dog("멍멍이", 100)); // 부모 타입은 자식을 담을 수 있다
Animal animal = animalBox.get();       // 꺼낼 땐 Animal 타입
  • Animal을 부모로 Dog, Cat이 sound()를 오버라이딩하는 구조.
  • Box<Dog>는 Dog만 받는다 → 타입 안전성을 눈으로 확인할 수 있다.
  • Box<Animal>에서 T는 Animal이므로, set(Animal)에 자식인 Dog·Cat도 다형성으로 들어간다. 대신 꺼낼 때는 Animal로 나오므로, Dog로 쓰려면 다운캐스팅이 필요하다.

정리

  • 타입별 클래스 → 중복, Object → 안전성 상실, 제네릭 → 둘 다 해결.
  • 제네릭의 본질은 타입 결정을 사용 시점으로 미루는 것 — 메서드 매개변수가 값 결정을 미루는 것과 같은 구조다.
  • 타입 인자는 참조형만 가능, 로우 타입은 쓰지 않는다.
