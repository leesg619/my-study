7. 컬렉션 프레임워크 - HashSet

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 2편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

MyHashSetV1 — 해시로 평균 O(1) 달성

public class MyHashSetV1 {
    static final int DEFAULT_INITIAL_CAPACITY = 16;
    LinkedList<Integer>[] buckets;
    private int size = 0;
    private int capacity = DEFAULT_INITIAL_CAPACITY;

    public boolean add(int value) {
        LinkedList<Integer> bucket = buckets[hashIndex(value)];
        if (bucket.contains(value)) {
            return false;
        }
        bucket.add(value);
        size++;
        return true;
    }

    public boolean remove(int value) {
        LinkedList<Integer> bucket = buckets[hashIndex(value)];
        boolean result = bucket.remove(Integer.valueOf(value)); // 값으로 삭제
        if (result) {
            size--;
        }
        return result;
    }
}
  • 앞 챕터의 해시 알고리즘을 그대로 Set에 적용했다. add/contains/remove 모두 해시 인덱스로 버킷을 찾은 뒤 그 안에서만 작업한다 → 평균 O(1), 전부 한 버킷에 몰리는 최악일 때만 O(n).
  • 함정: LinkedList.remove()는 오버로딩되어 있다. remove(int)는 인덱스로, remove(Object)는 값으로 지운다 → 값으로 지우려면 Integer.valueOf(value)로 넘긴다.
  • 한계: 숫자만 저장할 수 있다. 문자열은 어떻게 배열 인덱스로 바꾸지?

문자열을 해시 코드로

  • 컴퓨터는 문자를 이해하지 못하고, 모든 문자를 고유한 숫자로 다룬다 (ASCII 등의 코드표). 'A'는 65, 'B'는 66.
  • 즉, 문자열의 각 문자를 숫자로 바꿔 더하면 정수 하나를 얻을 수 있다.
static int hashCode(String str) {
    char[] charArray = str.toCharArray();
    int sum = 0;
    for (char c : charArray) {
        sum += c;
    }
    return sum;
}

static int hashIndex(int value) {
    return value % CAPACITY;
}

// "A" → 해시 코드 65 → 해시 인덱스 5
// "AB" → 해시 코드 131 → 해시 인덱스 1
용어의미
해시 함수임의 길이의 데이터를 받아 고정 길이의 해시 값으로 바꾸는 함수. 같은 입력엔 항상 같은 출력, 다른 입력이 같은 출력을 낼 수도 있다(충돌).
해시 코드데이터를 대표하는 값. 보통 해시 함수로 만든다. "A" → 65.
해시 인덱스데이터의 저장 위치. 보통 해시 코드를 배열 크기로 나눈 나머지.
  • 핵심: 어떤 타입이든 정수 해시 코드로 바꿀 수 있으면 해시 알고리즘을 태울 수 있다. 직접 만든 Member, User도 마찬가지 → 그래서 자바의 hashCode()가 등장한다.

자바의 hashCode()

  • 모든 객체가 해시 코드를 제공할 수 있도록 최상위 Object에 hashCode()가 있다.
  • Object의 기본 구현은 객체의 참조값을 기반으로 한다 → 내용이 같아도 인스턴스가 다르면 해시 코드가 다르다. 그래서 보통 재정의해서 쓴다.
  • Integer, String 같은 기본 클래스는 내부 값을 기반으로 이미 재정의되어 있다. Integer(10) → 10, "A" → 65.
    • 문자열은 단순 합이 아니라 충돌을 줄이도록 더 복잡하게 계산해서 큰 수가 나오고, 음수가 나오기도 한다.
public class Member {
    private String id;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Member member = (Member) o;
        return Objects.equals(id, member.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id); // id가 같으면 같은 해시 코드
    }
}
  • 동일성(==): 물리적으로 같은 인스턴스인가. 동등성(equals()): 논리적으로 같은가. 이 회원은 id가 같으면 같은 회원이다.
  • equals()와 hashCode()는 같은 기준으로 맞춘다. IDE가 멤버 변수를 골라 함께 생성해 준다.

MyHashSetV2 — 모든 타입 저장

public class MyHashSetV2 {
    LinkedList<Object>[] buckets;

    public boolean add(Object value) { ... }

    private int hashIndex(Object value) {
        return Math.abs(value.hashCode()) % capacity;
    }
}
  • int로 받던 곳을 모두 Object로 바꾼다.
  • value.hashCode()를 호출하면 다형성으로 실제 타입(String 등)의 재정의된 메서드가 실행된다. 타입과 상관없이 해시 코드를 얻을 수 있다.
  • 해시 코드는 음수일 수 있고 배열 인덱스는 음수가 안 된다 → Math.abs()로 양수로 바꾼 뒤 나머지 연산을 한다.

직접 만든 객체 보관 — 왜 equals와 hashCode가 둘 다 필요한가

  • MyHashSetV2는 Object를 받으므로 Member도 넣을 수 있다. 이때 equals(), hashCode() 둘 다 구현하지 않으면 장애로 이어진다.
  • hashCode()는 위치를 찾고, equals()는 그 위치에서 진짜 같은 값인지 최종 확인한다. 버킷의 contains() 내부에서 equals()가 호출된다.
  • 값이 하나만 있어도 equals()가 필요하다. 해시 인덱스가 같다고 같은 데이터라는 보장이 없다 — 강의 예제(버킷 10개)의 hi와 JPA는 같은 0번 버킷에 들어간다.
구현 상태같은 id의 두 객체 저장새 객체로 검색이유
둘 다 없음중복 저장실패참조값이 다르니 해시 코드가 달라 다른 버킷으로 간다
hashCode만중복 저장실패같은 버킷엔 가지만 equals가 참조값으로 비교해 다른 객체로 본다
equals만대개 중복 저장대개 실패해시 코드가 달라 엉뚱한 버킷을 찾아 비교 자체를 못 한다
둘 다 구현중복 거부성공같은 버킷을 찾고, equals로 같은 값임을 확인한다
  • 규칙: equals()가 true면 hashCode()도 반드시 같아야 한다. 반대로 해시 코드가 같다고 equals()가 true일 필요는 없다.
  • 이 메서드들은 해시 자료 구조(HashSet, HashMap 등)를 쓸 때 필요하다. 리스트만 쓸 때는 필요 없을 수도 있다.

좋은 해시 함수

  • 같은 입력엔 항상 같은 값을 내고, 값이 고르게 분포해서 충돌이 적어야 한다. 해시 코드가 한쪽으로 몰리면 버킷 하나에 데이터가 쌓여 O(n)에 가까워진다.
  • 직접 궁리할 필요 없이 자바의 Objects.hash()를 쓰면 된다.
  • 그래도 충돌은 일어난다. "Aa"와 "BB"는 해시 코드가 같다. 하지만 equals()로 다시 비교하므로 정확성에는 문제가 없다.

MyHashSetV3 — 제네릭과 인터페이스

public interface MySet<E> {
    boolean add(E element);
    boolean remove(E value);
    boolean contains(E value);
}

public class MyHashSetV3<E> implements MySet<E> {
    private LinkedList<E>[] buckets;
    ...
}
  • Object를 E로 바꿔 타입 안전성을 얻는다.
  • 핵심 기능을 인터페이스로 분리하면 해시 기반이 아닌 다른 자료 구조로도 Set을 구현할 수 있다 → 이어지는 자바의 TreeSet 등이 그 예.

정리

  • 어떤 객체든 hashCode()로 정수를 얻으면 해시 인덱스로 바꿀 수 있다 → 평균 O(1).
  • 저장·검색 모두 hashCode()로 위치를 찾고 equals()로 확인한다 → 직접 만든 객체를 해시 자료 구조에 넣으려면 둘 다 재정의해야 한다.
