12개 섹션 한 줄 회고

  • 클래스와 데이터 — 메서드 없이 데이터만 담는 클래스로 시작해, 참조가 실제로 어떻게 동작하는지부터 확실히 다졌다(구조체에 가까운 형태로 참조 개념을 먼저 익힌 셈).
  • 기본형과 참조형 — 값 복사냐 참조값 복사냐의 차이. 강의 스스로 "자바 개발자를 거르는 거름망"이라 부를 만큼 이후 모든 내용의 토대가 됐다.
  • 객체 지향 프로그래밍 — 데이터(클래스)와 기능(메서드)을 하나로 묶으면서 절차 지향과 다른 객체 지향의 출발점이 됐다.
  • 생성자·패키지·접근 제어자 — 객체 생성을 강제·보장하는 생성자, 클래스를 묶는 패키지, 그리고 캡슐화를 완성하는 접근 제어자까지 — "데이터는 감추고 필요한 기능만 공개한다"는 원칙으로 수렴했다.
  • 자바 메모리 구조와 static — 메서드·스택·힙 세 영역과, 클래스에 딱 하나만 존재하는 static의 관계를 스택/큐 자료구조 비유로 설명했다.
  • final, 상속, 다형성1·2, 다형성과 설계 — 부모의 기능을 물려받는 상속에서 시작해, 다형적 참조 + 메서드 오버라이딩이라는 두 축으로 객체지향의 꽃인 다형성을 완성했다. 추상 클래스·인터페이스는 모두 "제약이 추가된 다형성 구현체"라는 하나의 관점으로 정리됐고, 마지막엔 역할과 구현의 분리, OCP 원칙까지 실전 설계로 이어졌다.

객체지향은 원래 어렵다

  • 이 코스 내용을 80% 이상 이해했다면 프로그래머로서 적성이 있다고 볼 수 있다는 게 강의의 평가 기준이다 — 처음 한 번에 다 이해되지 않는 게 오히려 정상이라는 것.
  • 이해가 막히면 복습으로 익숙해지는 과정이 필요하고, 여러 번 반복해도 여전히 어렵다면 그때 적성을 진지하게 고민해봐도 된다는 현실적인 조언으로 마무리한다.

앞으로의 로드맵

  • 실전 자바 로드맵: 입문편·기본편에 이어 중급편·고급편이 이어진다.
  • 실전 데이터베이스 로드맵: 백엔드 개발자에게 필수적인 DB 지식을 실무 중심으로 다루는 과정.
  • 백엔드 개발자 로드맵: 스프링 프레임워크와 JPA를 활용한 실무 과정 — 스프링은 "객체지향(특히 다형성)을 편리하게 쓸 수 있게 해주는 도구 모음"이라는 관점에서, 지금까지 배운 다형성이 왜 중요한지가 다시 한번 강조된다.
  • 권장 순서는 자바 로드맵 → 데이터베이스 로드맵 → 스프링이지만, 취업 준비 등으로 시간이 빠듯하다면 자바의 예외 처리·컬렉션 정도만 익히고 바로 스프링 로드맵으로 넘어가는 것도 현실적인 대안으로 제시된다.

정리

  • 이 코스의 축은 결국 "참조"(클래스와 데이터)에서 시작해 "다형성"(상속·오버라이딩·역할과 구현의 분리)으로 완성되는 한 줄기 흐름이다.
  • 여기서 다진 기본기 — 특히 기본형/참조형의 차이와 다형성 — 는 스프링을 포함한 자바 생태계 전반의 코드를 읽고 쓰는 데 계속 다시 마주치게 된다.
  • 다음 단계는 실전 자바 중급편(컬렉션·제네릭 등)과 데이터베이스, 그리고 스프링 — 지금 다진 기본기가 그 내용을 이해하는 토대가 된다.
