순회 — Iterable과 Iterator

  • 순회: 자료 구조의 데이터를 차례대로 접근해서 처리하는 것.
  • 문제: 배열 리스트는 인덱스로, 연결 리스트는 node.next로, 해시 구조는 또 다르게… 자료 구조마다 순회 방법이 다르고, 내부 구조까지 알아야 한다.
  • 해결: 어떤 자료 구조든 같은 방법으로 순회하도록 인터페이스로 추상화한다.
    • Iterable(반복 가능한): iterator()로 반복자를 돌려준다.
    • Iterator(반복자): hasNext()로 다음 값이 있는지 묻고, next()로 값을 꺼내며 이동한다.
public class MyArrayIterator implements Iterator<Integer> {
    private int currentIndex = -1;
    private int[] targetArr;

    public MyArrayIterator(int[] targetArr) { this.targetArr = targetArr; }

    @Override
    public boolean hasNext() { return currentIndex < targetArr.length - 1; }

    @Override
    public Integer next() { return targetArr[++currentIndex]; }
}

public class MyArray implements Iterable<Integer> {
    private int[] numbers;

    public MyArray(int[] numbers) { this.numbers = numbers; }

    @Override
    public Iterator<Integer> iterator() {
        return new MyArrayIterator(numbers);
    }
}
  • 반복자는 자기가 순회할 대상의 참조를 들고, 현재 위치를 스스로 관리한다.
  • 구현체는 자료 구조마다 다르지만, 쓰는 쪽은 Iterator 인터페이스만 알면 된다.

향상된 for문의 비밀

for (int value : myArray) {          // 이렇게 쓰면
    System.out.println(value);
}

Iterator<Integer> it = myArray.iterator(); // 컴파일러가 이렇게 바꿔 준다
while (it.hasNext()) {
    int value = it.next();
    System.out.println(value);
}
  • 향상된 for문은 배열 또는 Iterable 구현체에 쓸 수 있다. Iterable이 아니면 컴파일 오류가 난다.
  • 강의의 표현을 빌리면: 만드는 사람이 수고로우면 쓰는 사람이 편하고, 만드는 사람이 편하면 쓰는 사람이 수고롭다.

자바의 컬렉션과 Iterable

  • Collection이 Iterable을 상속하므로 List, Set, Queue 등 모든 컬렉션을 같은 방식으로 순회할 수 있다.
  • Map은 Collection이 아니어서 바로 순회할 수 없다 → keySet(), values(), entrySet()을 통해 순회한다.
  • ArrayList의 반복자는 내부 클래스 Itr이고, HashSet은 HashMap의 KeyIterator를 쓴다. 쓰는 쪽은 몰라도 된다.
private static void printAll(Iterator<Integer> iterator) { ... }
private static void foreach(Iterable<Integer> iterable) { ... }

printAll(list.iterator());
printAll(set.iterator());
foreach(list);
foreach(set);
  • 인터페이스로 받으면 어떤 컬렉션이든 메서드 하나로 처리할 수 있다 → 다형성으로 재사용성이 극대화된다. 새 자료 구조도 두 인터페이스만 구현하면 기존 코드가 그대로 동작한다.
  • 내부 표현을 노출하지 않고 순차 접근을 제공하는 이 구조가 이터레이터 패턴이다.

정렬 — Comparable과 Comparator

  • Arrays.sort()로 간단히 정렬한다. 자바는 기본형 배열에 듀얼 피벗 퀵소트, 객체 배열에 팀소트를 사용하며 평균 O(n log n)이다.
  • 정렬 알고리즘의 핵심은 두 값을 비교하는 것이고, 비교 기준만 바꾸면 결과가 달라진다. 자바는 복잡한 알고리즘은 숨기고 기준만 인터페이스로 추상화했다.

Comparator — 비교 기준을 외부에서 제공

static class AscComparator implements Comparator<Integer> {
    @Override
    public int compare(Integer o1, Integer o2) {
        return (o1 < o2) ? -1 : ((o1 == o2) ? 0 : 1);
    }
}

Arrays.sort(array, new AscComparator());                // 오름차순
Arrays.sort(array, new DescComparator());               // 내림차순
Arrays.sort(array, new AscComparator().reversed());     // 뒤집기
  • 규칙: 첫 번째 값이 작으면 음수, 같으면 0, 크면 양수.
  • 내림차순은 결과에 -1을 곱하거나, reversed()로 뒤집는다.

Comparable — 객체의 기본 순서

public class MyUser implements Comparable<MyUser> {
    private String id;
    private int age;

    @Override
    public int compareTo(MyUser o) {
        return this.age < o.age ? -1 : (this.age == o.age ? 0 : 1); // 나이 오름차순
    }
}

public class IdComparator implements Comparator<MyUser> {
    @Override
    public int compare(MyUser o1, MyUser o2) {
        return o1.getId().compareTo(o2.getId());
    }
}

Arrays.sort(users);                    // Comparable 사용 — 나이순
Arrays.sort(users, new IdComparator()); // Comparator 우선 — 아이디순
  • 직접 만든 객체는 뭐가 더 큰지 자바가 알 수 없다 → Comparable을 구현해 "나는 비교할 수 있다"고 알린다. 이 기본 순서를 자연 순서(natural ordering)라고 한다.
  • 기본 순서 외의 기준이 필요하면 Comparator를 넘긴다. Comparator가 있으면 그쪽이 우선이다.
  • 둘 다 없으면 ClassCastException이 발생한다. Integer, String 같은 기본 클래스는 이미 Comparable을 구현하고 있다.

컬렉션 정렬

list.sort(null);                    // 자연 순서
list.sort(new IdComparator());      // 기준 지정
Collections.sort(list);             // 옛 방식 — list.sort() 권장

Set<MyUser> treeSet = new TreeSet<>();                   // Comparable 사용
Set<MyUser> idSet = new TreeSet<>(new IdComparator());   // Comparator 사용
  • 정렬은 순서가 있는 List 같은 자료 구조에 쓴다.
  • 객체가 자기 데이터를 스스로 정렬하는 list.sort()가 더 객체지향적이고 Java 1.8에 추가된 방식이라 이쪽을 권장한다.
  • TreeSet, TreeMap은 저장 시점에 왼쪽·오른쪽을 결정해야 하므로 비교 기준이 필수다. 없으면 역시 ClassCastException.

컬렉션 유틸

Collections.max(list);
Collections.min(list);
Collections.shuffle(list);   // 무작위로 섞기
Collections.sort(list);
Collections.reverse(list);

List<Integer> list = List.of(1, 2, 3);   // 불변 — add 시 UnsupportedOperationException
Set<Integer> set = Set.of(1, 2, 3);
Map<Integer, String> map = Map.of(1, "one", 2, "two");

List<Integer> mutable = new ArrayList<>(list);              // 불변 → 가변
List<Integer> unmodifiable = Collections.unmodifiableList(mutable); // 가변 → 불변

List<Integer> empty = List.of();          // 빈 불변 리스트 (Collections.emptyList()보다 간결)

List<Integer> synced = Collections.synchronizedList(mutable); // 멀티스레드용
  • 결과가 없을 때 null 대신 빈 리스트를 돌려주는 편이 나은 경우가 많다.
  • Arrays.asList()는 크기가 고정되어 add/remove는 안 되지만 set으로 값을 바꿀 수는 있는 애매한 리스트다. Java 9 이상이면 일반적으로 List.of()를 권장한다.
  • synchronizedList는 동기화 작업 때문에 일반 리스트보다 느리다. 지금은 존재만 알아 두고, 멀티스레드를 배운 뒤 다시 보면 된다.

컬렉션 프레임워크 전체 정리

데이터 그룹을 저장하고 처리하는 통합 구조로, 인터페이스 + 구현체 + 알고리즘으로 이루어진다.

Iterable
└─ Collection
   ├─ List   : ArrayList, LinkedList
   ├─ Set    : HashSet, LinkedHashSet, TreeSet
   └─ Queue  : ArrayDeque, LinkedList, PriorityQueue
      └─ Deque

Map          : HashMap, LinkedHashMap, TreeMap  (Collection 상속 안 함)
  • Collection은 add, remove, size, isEmpty, contains, iterator, clear 같은 공통 기능의 규약이다 → 일관성, 재사용성, 확장성, 다형성을 확보한다.
  • 알고리즘은 List.sort()처럼 자료 구조 자체에 있거나, Collections·Arrays의 정적 메서드로 제공된다.
  • PriorityQueue: 들어온 순서가 아니라 우선순위대로 처리한다. 놀이공원의 하이패스처럼.

  • 해시 기반은 평균 O(1), 트리 기반은 O(log n)이다. 정렬이 꼭 필요한 게 아니면 해시를 쓴다.
  • 실무에서 가장 많이 쓰는 건 List와 Map이다.

정리

  • 순회는 Iterable·Iterator로, 정렬 기준은 Comparable·Comparator로 추상화했다 → 쓰는 쪽은 구현을 몰라도 된다.
  • 컬렉션 프레임워크는 인터페이스와 알고리즘이 맞물리도록 처음부터 설계된 구조다.
