3. 컬렉션 프레임워크 - ArrayList

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 2편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

배열 — 인덱스는 빠르고, 검색은 느리다

  • 여러 데이터를 구조화해서 다루는 방법이 자료 구조이고, 자바는 이를 컬렉션 프레임워크로 제공한다. 그 출발점이 배열이다.
  • 인덱스로 입력·변경·조회: 한 번의 계산으로 위치를 찾는다. 데이터가 아무리 많아도 똑같이 빠르다.
    • 배열은 메모리에 연속으로 잡히고 칸 크기가 같다 (int라면 4byte).
    • 위치 = 배열 시작 주소 + (타입 크기 × 인덱스) → 끝까지 훑을 필요 없이 주소를 바로 계산한다.
  • 값으로 검색: 저장된 값을 알려면 열어 봐야 한다 → 처음부터 끝까지 비교하는 순차 검색이 필요하고, 크기가 n이면 최악의 경우 n번 비교한다.

빅오(O) 표기법

  • 정확한 실행 시간이나 연산 횟수를 세는 게 아니라, 데이터가 많아질 때 성능이 어떻게 변하는지 그 추세를 보는 도구다.
표기이름느낌예
O(1)상수 시간데이터 양과 무관배열 인덱스 접근
O(log n)로그 시간많아져도 거의 안 느려짐트리 구조 탐색
O(n)선형 시간데이터에 비례순차 검색
O(n log n)O(n)보다 조금 더 느림효율적인 정렬
O(n²)제곱 시간조금만 늘어도 급증이중 for문
  • 상수는 버린다: 데이터가 매우 크다고 가정하면 +2, /2 같은 값은 영향이 미미하다 → O(n + 2), O(n/2)도 그냥 O(n).
  • 별말이 없으면 최악의 경우를 기준으로 표기한다. 순차 검색은 운이 좋으면 O(1), 최악은 O(n), 평균은 O(n/2)인데 상수를 빼면 O(n).
  • 10만 건에서 인덱스 접근은 1번, 순차 검색은 최악 10만 번 → 인덱스를 쓸 수 있으면 최대한 활용한다.

배열에 데이터 추가 — 위치가 성능을 가른다

  • "추가"는 기존 값을 유지한 채 끼워 넣는 것이다. 빈 공간을 만들려면 기존 데이터를 오른쪽으로 밀어야 한다.
  • 끝에서부터 밀어야 한다. 앞에서부터 복사하면 다음 칸의 값을 덮어써 버린다.
추가 위치위치 찾기밀기합계
맨 앞O(1)전부 이동 O(n)O(n)
중간O(1)평균 절반 이동 O(n/2)O(n)
맨 끝O(1)이동 없음O(1)
 
private static void addAtIndex(int[] arr, int index, int newValue) {
    for (int i = arr.length - 1; i > index; i--) {
        arr[i] = arr[i - 1]; // 끝에서부터 오른쪽으로 한 칸씩
    }
    arr[index] = newValue;
}
  • 배열의 불편함 2가지: ① 생성할 때 크기가 고정된다 ② 데이터를 미는 코드를 매번 직접 짜야 한다 → 이걸 해결한 자료 구조가 리스트다.

직접 만드는 배열 리스트

리스트 = 순서가 있고, 중복을 허용하고, 크기가 동적으로 변하는 자료 구조. 배열을 내부에 감춰서 이런 편의를 제공하는 게 배열 리스트다.

V1 — 기본 구조

public class MyArrayListV1 {
    private static final int DEFAULT_CAPACITY = 5;
    private Object[] elementData;
    private int size = 0;

    public MyArrayListV1() { elementData = new Object[DEFAULT_CAPACITY]; }

    public void add(Object e) { elementData[size] = e; size++; }
    public Object get(int index) { return elementData[index]; }

    public Object set(int index, Object element) {
        Object oldValue = get(index);
        elementData[index] = element;
        return oldValue;
    }
}
  • capacity(배열 크기)와 size(실제 데이터 수)는 다르다. size가 다음에 넣을 위치 역할도 한다.
  • indexOf()는 size까지 돌며 equals()로 찾고, 없으면 -1. toString()은 Arrays.copyOf(elementData, size)로 실제 데이터만 잘라서 출력한다.
  • 강의 목적상 인덱스 검증 같은 코드는 생략했다.
  • 꽉 찬 상태에서 더 넣으면 ArrayIndexOutOfBoundsException → 자동으로 늘어나야 한다.

V2 — 동적 배열

public void add(Object e) {
    if (size == elementData.length) {
        grow();
    }
    elementData[size] = e;
    size++;
}

private void grow() {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity * 2;
    elementData = Arrays.copyOf(elementData, newCapacity);
}
  • 배열 자체는 늘릴 수 없다 → 더 큰 새 배열을 만들고, 값을 복사하고, 참조를 바꾼다. 참조를 잃은 옛 배열은 GC 대상이 된다.
  • Arrays.copyOf(원본, 새 길이)가 생성과 복사를 한 번에 해 준다.
  • 왜 2배? 1칸씩 늘리면 복사가 너무 자주 일어나고, 너무 크게 늘리면 메모리가 낭비된다 → 그 사이의 균형. 자바의 ArrayList는 약 50%씩 늘린다.
  • 사용하는 쪽은 내부 사정을 몰라도 그냥 넣으면 된다 — 이게 추상화의 편리함이다.

V3 — 원하는 위치에 추가·삭제

public void add(int index, Object e) {
    if (size == elementData.length) {
        grow();
    }
    shiftRightFrom(index);
    elementData[index] = e;
    size++;
}

public Object remove(int index) {
    Object oldValue = get(index);
    shiftLeftFrom(index);
    size--;
    elementData[size] = null; // 끝자리 비우기
    return oldValue;
}
  • 위치를 찾는 건 O(1)이지만, 데이터를 밀거나 당기는 쉬프트가 O(n) → 앞·중간 작업이 느린 이유.
  • 삭제 후 마지막 자리를 null로 비워 안 쓰는 객체가 GC될 수 있게 한다.

V4 — 제네릭 도입, 그런데 내부 배열은 왜 Object[]?

public class MyArrayListV4<E> {
    private Object[] elementData;

    public MyArrayListV4(int initialCapacity) {
        elementData = new Object[initialCapacity]; // new E[...]는 불가능
    }

    public void add(E e) { ... }

    @SuppressWarnings("unchecked")
    public E get(int index) {
        return (E) elementData[index];
    }
}
  • Object로 받던 V3는 숫자 리스트에 문자열이 들어가도 막지 못해, 꺼낼 때 ClassCastException이 터진다 → 제네릭 도입. E는 Element의 약자.
  • new E[capacity]는 불가능하다. 타입 이레이저로 런타임에 E의 정보가 없기 때문 → 내부 배열은 Object[]로 둘 수밖에 없다.
  • 그래도 안전하다: Object[]에는 무엇이든 담을 수 있고, add(E)라는 입구가 E만 받도록 막았으므로 배열에는 항상 E만 들어 있다 → 꺼낼 때의 (E) 캐스팅도 항상 성공한다. 그래서 @SuppressWarnings("unchecked")로 경고를 숨긴다.

정리 — 배열 리스트의 성능과 한계

연산빅오
마지막에 추가·삭제O(1)
앞·중간에 추가·삭제O(n)
인덱스 조회O(1)
값 검색O(n)
  • 순서대로 뒤에 넣고 뒤에서 빼는 작업에 강하다.
  • 한계 ① 정확한 크기를 모르면 뒤쪽 빈 공간이 메모리 낭비가 된다 ② 앞·중간 추가·삭제가 느리다 → 이를 보완하는 게 다음 챕터의 연결 리스트.
