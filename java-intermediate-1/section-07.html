7. 중첩 클래스, 내부 클래스 1

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 1편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

중첩 클래스란?

  • 클래스 안에 클래스를 정의하는 것 — for문 안에 for문을 넣는 것과 비슷한 "중첩" 구조.
  • 정의 위치가 변수 선언 위치와 대응된다: static이 붙으면 정적 중첩 클래스(정적 변수 자리), 안 붙으면 내부 클래스(인스턴스 변수 자리) — 내부 클래스는 다시 지역 클래스(지역 변수 자리)와 익명 클래스(이름 없는 지역 클래스)로 나뉜다.
  • 용어 구분: 중첩(Nested)은 "다른 것 안에 위치한다"는 구조적 관계일 뿐이고, 내부(Inner)는 "나를 구성하는 요소"라는 더 강한 관계 — 상자 안의 상자(중첩) vs 심장처럼 나를 이루는 부분(내부).
  • 핵심 판단 기준: 바깥 클래스의 인스턴스에 소속되는가? 정적 중첩 클래스는 소속되지 않고, 내부 클래스는 소속된다.
  • 엄밀히는 정적 중첩 클래스를 "내부 클래스"라고 부르면 안 되지만, 실무에서는 용어를 뭉뚱그려 쓰는 경우가 많다.
  • 사용 시점: 어떤 클래스가 특정 클래스 안에서만 쓰이거나 그 클래스와 아주 긴밀할 때만 중첩시킨다. 그렇지 않으면 그냥 밖으로 빼는 게 맞다.
  • 쓰는 이유는 두 가지 — 논리적 그룹화(관련된 걸 한데 묶음)와 캡슐화(바깥 클래스의 private 멤버에 접근할 수 있어 불필요한 public 메서드를 만들지 않아도 됨).

정적 중첩 클래스

  • 멤버 접근 규칙: 자기 자신의 멤버는 당연히 접근 가능. 바깥 클래스의 인스턴스 멤버는 접근 불가(애초에 static이라 특정 인스턴스와 엮여 있지 않음). 바깥 클래스의 정적 멤버는 접근 가능(클래스 영역에 있으니까).
  • 유일한 특권: 바깥 클래스의 private 멤버(정적 멤버 한정)에도 접근할 수 있다 — 같은 클래스 범위 안에 있다고 취급되기 때문.
  • 생성 방법: new Outer.Nested(). 실제 클래스 이름은 Outer$Nested 형태로 관리된다.
  • 결론: 정적 중첩 클래스는 바깥 클래스와 인스턴스 차원에서는 아무 관계가 없다 — "그냥 다른 클래스를 안에 넣어둔 것"과 다름없고, private 접근 가능이라는 점만 일반 클래스와 다르다.
class Outer {
    private static int classValue = 1;

    static class Nested {
        void method() {
            System.out.println(classValue); // 바깥 클래스의 private static 필드 접근 가능
        }
    }
}
// 생성: new Outer.Nested()

정적 중첩 클래스의 활용

  • 예시: NetworkMessage가 Network 클래스 안에서만 쓰인다고 하자. 이 둘을 별개 파일(클래스)로 두면, 이 패키지를 처음 보는 개발자는 두 클래스를 다 훑어봐야 하고 "이 둘을 같이 써야 하나?" 헷갈린다.
  • NetworkMessage를 Network 안에 private static으로 중첩시키면, 외부에서는 아예 접근할 수 없게 되어 "이건 Network 내부 전용"이라는 의도가 코드 구조만으로 명확해진다.
  • 규칙: 소속된 바깥 클래스 안에서 쓸 때는 바깥 클래스 이름 없이 그냥 NetworkMessage로 쓰면 되고, 외부에서 접근해야 한다면 Network.NetworkMessage 형태가 필요하다. 만약 외부에서 자주 접근해야 하는 상황이 된다면, 그건 애초에 중첩 클래스로 만든 게 잘못된 것 — 별도 클래스로 분리해야 한다.

내부 클래스

  • 정적 중첩 클래스와 정반대 — static이 없고, 바깥 클래스의 인스턴스에 소속된다.
  • 그래서 내부 클래스는 자기 멤버뿐 아니라 바깥 클래스의 인스턴스 멤버와 클래스 멤버 모두 접근 가능하다(private 포함).
  • 생성 방법이 다르다: 바깥 인스턴스 없이는 만들 수 없다 — Outer outer = new Outer(); Outer.Inner inner = outer.new Inner();.
  • 내부적으로 내부 인스턴스가 바깥 인스턴스 "안에" 물리적으로 들어있는 건 아니고, 둘은 별개로 만들어지되 내부 인스턴스가 바깥 인스턴스의 참조를 들고 있는 구조다.
class Outer {
    int instanceValue = 1;

    class Inner {
        void method() {
            System.out.println(instanceValue); // 바깥 인스턴스 멤버 접근 가능
        }
    }
}
// 생성: outer.new Inner()

내부 클래스의 활용

  • 예시: Engine이 Car의 model, chargeLevel 정보가 필요한데, Engine이 Car 밖의 별개 클래스라면 Car는 getModel(), getChargeLevel()을 public으로 열어줘야 한다 — 캡슐화가 깨진다.
  • Engine을 Car의 내부 클래스로 만들면, Engine이 바깥 인스턴스(Car)의 필드에 직접 접근할 수 있으니 그 getter들을 아예 없앨 수 있다.
  • 중첩 클래스를 쓸지 말지 판단 기준은 결국 동일 — 특정 클래스 안에서만 쓰이거나 매우 긴밀할 때만. 정적 중첩은 "그냥 안에 넣어둔 독립적인 클래스"이고, 내부 클래스는 "바깥 인스턴스와 실제로 얽혀서 동작하는 구성 요소"라는 차이가 있을 뿐 활용 판단 기준(논리적 그룹화 + 캡슐화)은 같다.

같은 이름의 바깥 변수 접근

  • 내부 클래스, 바깥 클래스, 지역 변수에 같은 이름의 변수가 있으면 더 가까운(구체적인) 것이 우선된다 — 지역 변수 > 내부 클래스 인스턴스 변수 > 바깥 클래스 인스턴스 변수.
  • 이렇게 앞선 변수를 가려서 안 보이게 되는 현상을 shadowing이라 부른다.
  • 내부 클래스 자신의 인스턴스 변수를 명시적으로 가리키려면 this.value, 바깥 클래스의 인스턴스 변수를 가리키려면 Outer.this.value 문법을 쓴다.
  • 다만 이런 문법에 의존하기보다, 애초에 변수 이름을 겹치지 않게 짓는 게 훨씬 명확하다 — 프로그래밍에서 가장 중요한 건 결국 명확성.

정리

  • 중첩/내부를 가르는 핵심 질문은 "바깥 클래스의 인스턴스에 소속되는가?" — 정적 중첩 클래스는 아니고, 내부 클래스는 그렇다.
  • 정적 중첩 클래스는 사실상 독립된 클래스(바깥의 private static만 추가로 접근 가능), 내부 클래스는 바깥 인스턴스 없이는 존재할 수 없는 진짜 "구성 요소".
  • 둘 다 쓰는 이유는 같다 — 특정 클래스 안에서만 쓰이는 걸 논리적으로 묶고(그룹화), private 접근으로 불필요한 public API 노출 없이 긴밀하게 연결한다(캡슐화).
  • 외부에서 자주 쓰이게 된다면 애초에 중첩/내부 클래스로 설계한 게 잘못됐다는 신호 — 별도 클래스로 분리해야 한다.
  • 이름이 겹칠 때는 this/Outer.this로 구분할 수 있지만, 애초에 이름을 겹치지 않게 짓는 것이 더 명확한 코드다.
