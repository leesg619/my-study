9. 컬렉션 프레임워크 - Map, Stack, Queue

인프런 김영한 강사님의 "김영한의 실전 자바 - 중급 2편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

Map — 키와 값의 쌍

  • 키(Key)와 값(Value)을 연결해서 저장한다. 사전의 단어와 뜻, 주식 티커와 회사 이름, 학생 이름과 성적처럼.
  • 키는 유일해야 하고, 값은 중복될 수 있다. 순서는 보장하지 않는다.
  • 저장 방식이 달라서 Map은 Collection을 상속하지 않는 별도 인터페이스다.
Map<String, Integer> studentMap = new HashMap<>();
studentMap.put("studentA", 90);
studentMap.put("studentB", 80);

Integer score = studentMap.get("studentA");

Set<String> keySet = studentMap.keySet();               // 키 목록
Collection<Integer> values = studentMap.values();        // 값 목록

for (Map.Entry<String, Integer> entry : studentMap.entrySet()) {
    System.out.println(entry.getKey() + "=" + entry.getValue());
}
메서드반환 타입왜 그 타입인가
keySet()Set키는 유일하고 순서가 없다 → 딱 Set의 성질
values()Collection값은 중복될 수 있어 Set이 아니고, 순서가 없어 List도 아니다 → 상위 타입
entrySet()Set<Map.Entry>내부적으로 키·값을 Entry로 묶어 보관한다. getKey(), getValue() 제공

자주 쓰는 동작

studentMap.put("studentA", 100);    // 같은 키로 저장 → 기존 값이 교체된다
studentMap.containsKey("studentA"); // 키가 있는지
studentMap.remove("studentA");      // 키로 지우면 값까지 함께 사라진다

// 없을 때만 넣기 — containsKey + put을 한 줄로
studentMap.putIfAbsent("studentA", 100);

// 없으면 기본값으로 조회
studentMap.getOrDefault("studentZ", 0);

Map 구현체

  • 키만 떼어 보면 유일하고 순서가 없다 — Set과 같다. Map은 Set에 값을 붙인 것뿐이고, 둘의 구현은 거의 같다.
  • 실제로 HashSet은 내부에서 HashMap을 쓴다. 값 자리를 비워 두고 키만 쓰는 것이다. LinkedHashSet↔LinkedHashMap, TreeSet↔TreeMap도 마찬가지.
구현체순서성능
HashMap보장 안 함평균 O(1)
LinkedHashMap입력 순서평균 O(1), 링크만큼 추가 메모리
TreeMap키의 정렬 순서O(log n)
  • HashMap의 동작은 HashSet과 같다. 해시 코드는 키로만 계산하고 값은 관여하지 않는다. 키·값은 Entry 객체로 묶여 저장된다.
  • 키로 쓰는 객체는 hashCode()와 equals()를 반드시 구현해야 한다. 값은 필요 없다.
  • containsKey()는 O(1)이지만, containsValue()는 값을 전부 뒤져야 하므로 O(n)이다.
  • 실무에서 가장 많이 쓰는 건 HashMap. 순서나 정렬이 필요할 때만 나머지를 고른다.

Stack — 후입선출(LIFO)

  • 위만 열린 통에 블록을 쌓는 모습. 넣는 곳과 빼는 곳이 같아서 나중에 넣은 것이 먼저 나온다. 1, 2, 3을 넣으면 3, 2, 1로 나온다.
  • 넣기 push, 빼기 pop, 꺼내지 않고 보기 peek.
  • 뒤로 가기 같은 히스토리 기능에 어울린다.
  • 주의: java.util.Stack 클래스는 내부적으로 옛날 Vector를 쓰는 레거시로, 하위 호환 때문에 남아 있을 뿐이다 → 쓰지 말고 Deque를 쓴다.

Queue — 선입선출(FIFO)

  • 뒤로 넣고 앞으로 뺀다. 먼저 넣은 것이 먼저 나온다. 선착순 이벤트처럼 순서대로 처리할 때 쓴다.
  • 넣기 offer, 빼기 poll, 보기 peek.
  • 강사님의 비유: 냉장고는 입구가 하나라 스택이다. 먼저 넣은 콜라가 안쪽에 남아 유통기한을 넘기기 쉽다 → 뒤쪽에서 꺼내는 큐 구조였다면 그런 일이 없었을 것.
  • Queue는 Collection의 자식 인터페이스이고, 구현체로 ArrayDeque, LinkedList가 있다.
Queue<Integer> queue = new ArrayDeque<>();
queue.offer(1);
queue.offer(2);
queue.offer(3);

queue.peek(); // 1 — 꺼내지 않음
queue.poll(); // 1
queue.poll(); // 2

Deque — 양쪽 끝이 다 열린 구조

  • Double Ended Queue. 앞뒤 어디서든 넣고 뺄 수 있어 스택과 큐의 기능을 모두 포함한다. 데크, 덱 등으로 부른다.
Deque<Integer> deque = new ArrayDeque<>();
deque.offerFirst(1); // [1]
deque.offerFirst(2); // [2, 1]
deque.offerLast(3);  // [2, 1, 3]
deque.offerLast(4);  // [2, 1, 3, 4]

deque.peekFirst();   // 2
deque.peekLast();    // 4
deque.pollFirst();   // 2
deque.pollLast();    // 4

스택·큐로 쓰기 — 이름까지 제공된다

// 스택처럼
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
stack.pop(); // 2

// 큐처럼
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1);
queue.offer(2);
queue.poll(); // 1
  • Deque는 Queue의 자식 인터페이스다. 큐 기능만 필요하면 Queue 타입으로 받아 제약을 분명히 하는 편이 낫다.
  • 스택에는 그런 인터페이스가 없다. 이미 Stack이라는 이름을 클래스가 차지했고, 자바는 하위 호환을 중시해 고치지 않는다 → 스택은 Deque 타입으로 쓴다.

ArrayDeque vs LinkedList

  • 둘 다 이론상 앞뒤 작업이 O(1)이지만, 실제로는 ArrayDeque가 더 빠르다.
  • ArrayDeque는 배열을 원형 큐처럼 쓴다. 메모리가 연속이라 CPU 캐시에 유리하고, 노드를 만들 필요도 없다.
  • → 스택이나 큐가 필요하면 ArrayDeque.

정리

  • Map은 키가 곧 Set이다. 해시 코드는 키로만 계산하므로 키 객체에 hashCode()·equals()가 필수다. 강의 문제 풀이의 장바구니 예제에서도, 키로 쓰는 Product에 이 둘을 구현해 이름과 가격이 같으면 같은 상품으로 다뤘다.
  • Stack 클래스는 쓰지 않는다. 스택·큐 모두 ArrayDeque로.
  • 이것으로 자바에서 주로 쓰는 List, Set, Map, Stack, Queue를 모두 봤다.
