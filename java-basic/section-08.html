8. final

인프런 김영한 강사님의 "김영한의 실전 자바 - 기본편" 강의를 듣고 정리한 학습 노트입니다. 강의 PDF를 그대로 옮긴 것이 아니라, 강의에서 설명한 흐름과 예시를 제 나름대로 재구성했습니다.

final의 기본 의미 — "끝, 값이 들어오면 끝"

  • final이 붙은 변수는 딱 한 번만 값을 할당할 수 있고, 그 이후 다시 값을 바꾸려 하면 컴파일 오류가 난다.
  • 지역 변수: 선언과 동시에 초기화하거나, 선언 후 최초 대입 시점에 한 번만 값을 넣을 수 있다.
  • 매개변수: final을 붙이면 메서드 안에서 그 매개변수의 값을 바꿀 수 없다.
  • 필드(멤버 변수): 생성자를 통해 한 번만 초기화하거나, 필드 선언과 동시에 초기화할 수 있다. 생성자로 초기화하면 인스턴스마다 다른 값을 가질 수 있고, 필드에서 바로 초기화하면 모든 인스턴스가 같은 값을 갖는다(그리고 그 값은 다시 못 바꾼다).

static final — 상수

  • 필드를 선언과 동시에 초기화하는 final은 사실 인스턴스마다 같은 값을 중복해서 들고 있는 셈이라 메모리 낭비다 — 이럴 때 static까지 함께 붙이면, 그 값이 메서드 영역의 static 영역에 딱 하나만 존재하고 모든 인스턴스가 공유한다.
  • 이렇게 static final로 선언한 변경 불가능한 값을 상수(constant)라 부른다. 관례상 모두 대문자 + 단어는 언더스코어로 구분(MAX_USER)해서 이름 짓는다 — 일반 변수의 카멜케이스와 구분해 "이건 상수구나"를 한눈에 알아보게 하기 위함.
  • 상수는 기능이 아니라 고정된 값 자체를 쓰는 게 목적이라, final이 이미 변경을 막아주므로 public으로 필드를 직접 노출해도 캡슐화가 깨지는 문제가 생기지 않는다(Constants.PI처럼 클래스명으로 바로 접근).
class Constants {
    public static final double PI = 3.14159;
    public static final int MAX_USER = 1000;
}

Constants.MAX_USER // 클래스명으로 직접 접근

매직 넘버 문제

  • 코드 여기저기에 1000, 3.14 같은 숫자가 그냥 박혀 있으면("매직 넘버") 그 숫자가 무슨 의미인지 코드만 보고는 알기 어렵고, 값을 바꿔야 할 때 모든 사용처를 찾아 일일이 고쳐야 한다.
  • 상수로 뽑아내면(MAX_USER) 이름 자체가 의미를 설명해주고, 값을 바꿀 때도 상수 선언부 한 곳만 고치면 프로그램 전체에 일관되게 반영된다 — 상수의 "중앙 관리" 장점.

final과 참조형 변수 — 헷갈리기 쉬운 지점

  • 변수는 기본형(값 자체를 저장)과 참조형(객체의 참조값을 저장)으로 나뉜다는 걸 기억하자. final이 하는 일은 언제나 "그 변수에 저장된 값을 못 바꾼다"이다.
  • 기본형에 final을 붙이면 값 자체를 못 바꾼다 — 직관적이다.
  • 참조형에 final을 붙이면 그 변수가 담고 있는 참조값(어떤 객체를 가리키는지)을 못 바꾼다는 뜻이지, 그 객체 내부의 필드까지 못 바꾼다는 뜻이 아니다. final Data data = new Data(); 이후 data = new Data();(다른 객체로 재할당)는 컴파일 오류지만, data.value = 10;(같은 객체 내부 값 변경)은 아무 문제 없이 동작한다.
  • "final인데 왜 값이 바뀌지?"라는 오해가 여기서 자주 생긴다 — final이 잠그는 건 변수 자체(어느 객체를 가리키는가)이지 그 객체의 내부 상태가 아니라는 점을 구분해야 한다.
final Data data = new Data();
data.value = 10;     // OK — 객체 내부 값 변경
data = new Data();   // 컴파일 오류 — 참조 대상 자체를 바꾸려 함

final을 실무에서 쓰는 이유

  • 예: 고객 ID처럼 생성 이후 절대 바뀌면 안 되는 값에 final을 걸어두면, 누군가 실수로(혹은 몇 달 뒤 코드를 잊고) 그 값을 바꾸는 코드를 추가하려는 순간 컴파일러가 즉시 오류로 잡아준다.
  • final 없이 방치했다면, 실수로 바뀐 고객 ID 하나가 로그·결제·결제 이력 조회 등 시스템 전반에 조용히 잘못된 영향을 퍼뜨릴 수 있다 — 컴파일 시점에 막는 것과 런타임에 뒤늦게 발견하는 것의 차이는 크다.
  • final은 코드를 작성하는 시점에 "이 값은 절대 안 바뀐다"는 의도를 명시적으로 남기는 장치이기도 하다 — 나중에 그 코드를 다시 보는 사람(자신 포함)이 왜 이 값이 고정되어야 하는지 고민할 필요 없이 바로 알 수 있다.

정리

  • final은 지역 변수·매개변수·필드 어디에 붙든 "값을 한 번만 할당하고 더는 못 바꾼다"는 동일한 규칙을 강제한다.
  • static final로 상수를 만들면 메모리도 아끼고, 매직 넘버 문제도 해결하고, 값을 한 곳에서 관리할 수 있다 — 관례상 대문자+언더스코어로 명명한다.
  • 참조형 변수의 final은 "가리키는 대상"만 고정할 뿐, 그 대상 내부의 값까지 잠그지는 않는다는 점이 가장 헷갈리기 쉬운 함정이다.
  • 실무적으로 final은 "절대 바뀌면 안 되는 값"에 대한 실수 방지 장치이자, 코드 의도를 명확히 남기는 문서화 수단이다.
